# 24 · 技法台（测试版 v0.4）与全流程

> 代码：`src/views/TechniqueView.tsx` + `data/techniques.json`（20 条）
> 目标：把四个页面串成一条能走通的路，而不是四个孤岛。

## 1 · 全流程现在长这样

```
推荐台                分子台                技法台               配方台
选材料 + 调性   →   放一样料，挑分子   →   选技法 + 调参数   →   配比 + 读数 + 做法
   5 张方案卡          4 张配对建议          1 张备料卡            1 杯酒
        └────────────────┴──────────┬────────────┴──────────────────┘
                                    ↓
                                资料库（查分子/结构/反应）
```

四条交接都实测过：

| 从 | 到 | 带走什么 |
|---|---|---|
| 推荐 → 配方 | 5 张卡的配比 | `lines[]` |
| 分子 → 配方 | 主料 + 前两张配对 | `lines[]` |
| 技法 → 配方 | 主料 + 基酒 + 酸 + 苏打，加一个**备料 chip** | `lines[]` + `prep` |
| 任何 → 资料 | — | 页签跳转 |

## 2 · 技法台的三个决定

**① 参数是滑块 + 双色带。**
每个参数都有 `safe`（推荐区间，绿）与 `danger`（危险区间，红）。拖动时实时判断，落到危险区整行变红，右上角出「这套参数有问题」。

这比「填一个数字然后系统说不行」好——用户能看见墙在哪。

**② 时间轴用等宽列，不用比例宽。**
第一版按 `ph.to - ph.from` 分配宽度，结果「0–10 min」那格只剩 4% 宽，中文竖着排成一条线。改成等宽列、时间范围写在格子里 —— **信息密度比「比例精确」重要**。

**③ 产物卡只写三件事**：叫什么、多久内用完、有什么坑。
不编不存在的指标（浓度、得率），因为我算不出来。

## 6 · 修正：分子台的下游是技法台，不是配方台（v2.5）

第一版我图省事，把分子台的「送出去」直接接到了配方台——**接错了。**

这条链本来是有顺序的：

```
材料 → 分子（挑味道）→ 技法（决定怎么留住它）→ 配方（调比例）
```

挑完分子，下一个问题不是「放多少」，而是「**用什么手法把它留住**」。选青绿香和选焦糖香，答案完全相反：

- 青绿香（(Z)-3-己烯醛）在 65℃ 以上基本没了 → 只有 **快速浸渍 90 秒**能保
- 焦糖/木质（呋喃酮、愈创木酚）在低温下出不来 → 要 **低温慢煮 65℃ / 90 min**

所以技法台现在接收分子台的构成，并给出建议：

| 分子台选了什么 | 技法台推什么 | 为什么 |
|---|---|---|
| 青绿（green 香族） | T3 快速浸渍 | 65℃ 以上留不住，只有 90 秒能保 |
| 焦糖奶油 / 后调分子 | T1 低温慢煮 | 高温快出只会烤糊它 |
| 花香（floral） | T4 冷萃 | 最怕氧化和高温，4℃ / 12 h 最稳 |
| 主料带果胶 | T11 酶澄清 | 40–50℃ / 30 min 把浑浊变透明 |
| 都没有 | T1 低温慢煮 | 最稳的起点 |

配方台仍然是链条终点，通过「做成备料 → 送进配方台」进入，带 `prep` 标签。
