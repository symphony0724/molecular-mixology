# 23 · 分子台（单材料拆分，测试版 v0.3）

> 代码：`src/engine/pairing.ts` + `src/views/BenchView.tsx`
> 入口：页签第二格「分子 BENCH」——**主功能，不是二级页**
> 与 `samples/14-单材料分子台.html` 的差别：那张是画出来的，这张是算出来的。

## 1 · 它回答的问题

「我只有一样东西，怎么把它做成一件事？」

流程：**放一样材料 → 拆出它的主角分子 → 挑你想突出的 → 系统按分子关系推荐搭子 → 带着这几样去配方台**。

台面只放一样，是刻意的：放两样，这一步就退化成「勾清单」，和推荐台重复了。

## 2 · 配对不是查表，是算出来的

最初的设计要一张手写的 `pairs.json`（60–80 条配对规则），一直没写，因为没有它这个页面就跑不起来。这次换了个思路：**不写表，直接用已有的分子数据算三种关系**。

对每一样候选材料：

| 关系 | 判定条件 | 话术 |
|---|---|---|
| **同系叠加** | 候选里含有你已选的同一个分子 | 「丁酸乙酯 在这儿也有（高）——同一个分子两条来源，会被加厚，不是叠加第二种味道」 |
| **补空层** | 候选的分子和你已选的**同香族**，但落在**你还没选的时间层** | 「它带来 β-紫罗兰酮，和已选的熟果甜香同族，但在『后调』——补的是空着的那一层」 |
| **补香族** | 候选带来一个你和主料都还没有的香族 | 「它不在已选的香族里（花香），用来给整杯一个别的方向」 |

打分：`4 × 同系 + 2 × 补空层 + 1.2 × 补香族`，再按本批最高分归一化到 6–98。

三条限制：
- **同一香族最多两条**，否则推荐会变成「一整屏柑橘」。
- 每条都必须说出**是哪个分子、哪个香族、哪一层**，说不出来就不显示。
- 「难度」只有 `season` 一个字段可用，所以显示的是「3–7 月当季」，并且注明这是按季节推测，不是采购数据。

## 3 · 三种关系为什么这么算

**同系叠加**最好解释：两个材料共享同一个分子，浓度相加，同一种味道变浓。不需要假设，也不需要文献。

**补空层**来自「前中后调」的定义——不是玄学，是挥发时间。草莓的主调在前调（丁酸乙酯，几秒到几分钟），它的中后调是空的。要补的不是「更多草莓味」，而是空着的那一层。

**补香族**是兜底：如果既不共享分子，也不补空层，那它只能贡献一个新方向。这种情况分数最低，排在最后。

## 4 · 散点图怎么画

- 横轴：三个时间层（前 0–5 / 中 5–30 / 后 30+），一列一层
- 纵轴：阈值取对数，**范围按当前材料的分子动态算**（草莓只有 1e-3 ~ 0.04，就不该画到 1e-6，否则所有点挤在顶上）
- 空心＝未选，实心＝选中，点一下切换

之所以不做「分子球/3D 结构」，是因为**浓度只有分级估算、阈值才是文献值**。用阈值当坐标是诚实的，用浓度当坐标是编的。

## 5 · 现在的短板

| 缺什么 | 后果 |
|---|---|
| **`ingredients.json` 每样只有 3–7 个分子** | 草莓在数据里只有 3 个（丁酸乙酯 / 呋喃酮 / (Z)-3-己烯醛），样张里画的 7 个是我手写的。**这是目前最大的短板**——分子少，配对就少 |
| 技法台没做 | CTA 只能去配方台，去不了技法台 |
| 保存 | 挑了哪些分子不持久化 |
| 香型快选 | 样张里的「按香型快选」（与 05 共用选择状态）还没接 |
