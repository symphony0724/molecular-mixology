# 17 · 单材料分子台（v1.9）

> 样张：`samples/14-单材料分子台.html`（1440×900）
> 用户原话：*「我只有单一材料的时候，把材料放到操作台上之后展开它所有的风味分子，可以选择自己想要突出的风味，然后根据这个风味分子跟其他分子的搭配做推荐材料，不需要问都有什么，可以按照材料获取难易程度推荐，然后转到技法操作台」*

## 1 · 这个入口解决什么

推荐台（09）问「你有什么」——适合**已经有一堆材料**的人。

但真实场景里最常见的是：**冰箱里只有一样东西**。这时候问「你还有什么」是废话（用户就是没有），问「你想要什么风味」也太抽象（用户不知道该选哪个词）。

所以这个入口反过来：

```
不问有什么 → 只问「台上这一样是什么」
        ↓
把它拆成分子，让人看见「它其实是什么」
        ↓
勾选想突出的分子（这一步是用户的主动权）
        ↓
按「能和这些分子成立」+「有多容易买到」推荐材料
        ↓
带着材料清单去技法台
```

## 2 · 与 05 香调设计的关系

**05 是香型层（facet），14 是分子层。** 两者是同一个问题的两个粒度：

| | 05 香调设计 | 14 单材料分子台 |
|---|---|---|
| 选择单位 | 5 个香型（熟果甜香 / 青绿…） | 7–12 个具体分子 |
| 用户看到的 | 「你想要熟果甜香」 | 「它带丁酸乙酯 0.001 mg/L」 |
| 适合谁 | 不懂分子、只想描述「想要什么感觉」 | 想控制「突出哪一个分子」的人 |
| 数据依赖 | 分子 → 香族映射（已有） | **分子 → 分子配对规则（缺）** |

**建议：05 保留，但降级成 14 的一个「快捷视图」**——勾香型 = 批量勾选该香族的分子。这样两套界面共用一套选择状态，不会出现「05 选了花香、14 却没选中芳樟醇」的矛盾。

## 3 · 台面为什么是散点，不是分子球

每个分子有四个属性：阈值、沸点/logP（→ 时间层）、香族、浓度等级。

- **浓度等级**我们只有分级估算（dominant/mid/low），画成球的大小会假装精确。
- **阈值**是文献值，数量级可靠。
- **时间层**是推出来的，但边界清楚（0–5 / 5–30 / 30+）。

所以散点用 **x = 时间层、y = 对数阈值**，是「我们真的有的两个维度」，而不是「看起来最酷的两个维度」。

图上一眼能看出的两件事：

1. **草莓的 7 个分子横跨三个时间层**——它天然自带一套三调结构，不需要「补结构」。
2. **后调只有 2 个，且都在阈值高位（0.005、0.04）**——它们不容易被闻到，且都是「甜」。**缺的是一个「干」的收口**（这也是推荐里为什么把冷熏橡木单列出来，明知它「难」）。

## 4 · 推荐逻辑（需要新建的数据）

现在的 `ingredients.pairs` 只是**食材级**的「这俩能配」，不够用。需要新建 **分子配对规则表**：

```ts
type PairRule = {
  id: string;
  kind: "同系叠加" | "同族互补" | "对比" | "抑制" | "底味支撑";
  a: CompoundId; sm: string;      // 任一方的分子
  b: CompoundId | "role:sweetener" | "class:tannin";
  verdict: "strong" | "ok" | "avoid";
  mechanism: string;               // 为什么（必填）
  human: string;                   // 一句人话，界面直接显示
  evidence: "lit" | "mech" | "consensus";
};
```

样张里四条推荐的 `kind` 分别是：

| 推荐 | kind | 机制 |
|---|---|---|
| 菠萝 | 同系叠加 | 共用丁酸乙酯，多一个含硫「热带」分子，把熟果顶上去 |
| 香蕉 | 抑制（同向覆盖） | 乙酸异戊酯与丁酸乙酯同走酯香通路，量大压掉青绿 |
| 桂花 | 同族互补 | β-紫罗兰酮接住断掉的中调，和草莓芳樟醇同属花香线 |
| 冷熏橡木 | 对比 | 呋喃酮是纯甜，愈创木酚是烟熏的干——「焦糖布丁的壳」 |

注意第二条：**推荐里必须允许出现「不建议主用」**。只推「合适」的东西会让用户以为所有推荐都等价。

## 5 · 获取难度分级

用户没有材料清单，所以「可得性」必须由系统给出。三档，按「现在能不能拿到」而不是「贵不贵」：

| 档 | 判定 | 例子 |
|---|---|---|
| **易** | 超市/菜场常年有，不需要处理 | 菠萝、香蕉、柠檬、黄瓜 |
| **中** | 当季 / 需要网购 2–3 天 / 需要处理（泡发、熬煮） | 桂花（9–10 月）、香草荚、干香菇 |
| **难** | 专业渠道 / 需要设备或长时间处理 | 冷熏橡木片（要熏）、柚子苦精、酶制剂 |

默认**按易得排序**，因为用户此刻只想知道「今晚能做什么」。切换「按适配度」是给愿意等的人。

## 6 · 链路收口

推荐完不是结束，而是把三样材料直接带进技法台：

```
草莓 200 g · 菠萝 60 g · 桂花 1.5 g
        ↓ 推荐技法（按这批材料的角色匹配，见 docs/09）
T1 低温慢煮（65℃ 90 min） / T3 快速浸渍（90 s）
```

这和 04 技法推荐共用同一个 `TechniqueSolver.filter()`——**同一条链路只写一次**。

## 7 · 数据缺口（要补才能做真）

1. **分子配对规则表**（`data/pairs.json`）：现在 0 条。粗估 60–80 条能覆盖 12 香族的主要组合。
2. **获取难度字段**：`data/ingredients.json` 每条要加 `avail: "easy" | "mid" | "hard"` + `availNote`（哪个季节、哪里买）。
3. **单材料 → 分子清单**：已有（`aroma[]`），但一个材料只有 3–7 个分子（我们刻意只收「可解释的关键分子」）。**界面必须说清这不是「全部成分」**，否则用户会以为草莓只有 7 种分子。
4. **未选中的分子也要显示**：现在灰点是「未选」，但真实界面应该还能看见「草莓还有 20 多种分子，我们没收，因为它们不决定这杯的走向」。

## 8 · 待确认

1. 台面上**只许放一样材料**，还是允许放 2–3 样（先看它们的分子能不能叠）？
2. 散点图对普通用户是不是太难读？要不要默认给「按时间层分三列」的列表视图，散点作为「专业模式」里的视图？
3. 推荐里出现「不建议主用」（香蕉那条）合适吗？还是应该把它收进一个「可以但要注意」的折叠区？

## 9 · 已确认（v1.10）

用户 m01280：「1只要一种，2不需要，3可以，分子不需要全列出来，只需要风味突出的」

| # | 问题 | 结论 | 落到界面上的改动 |
|---|---|---|---|
| 1 | 台面放几样 | **只许一样** | 左栏改为「只放一样」，卡片下一行手写批注：「台面只放一样——放了第二样，这一步就退化成『勾清单』了」。**多材料的分子叠加方案作废**，不再设计 |
| 2 | 散点要不要换成列表 | **不用换**，散点保留为默认视图 | 不做「按时间层三列」的备选视图 |
| 3 | 05 香调设计怎么处理 | **降级为快捷视图** | 分子列表下加 `逐个挑分子 / 按香型快选` 切换 + 四个香型 chip（熟果 3 / 青绿 1 / 花香 1 / 焦糖 2），点香型 = 批量勾该族分子，**与 05 共用同一份选择状态** |
| 4 | 分子要不要全列 | **只列风味突出的** | 标题从「它带来 7 个分子」改为「**它的主角分子 7 / 约 30**」，并加脚注：「只列决定这杯走向的 7 个；另外 20 多种含量在阈值以下，不进来」 |

同时删掉了左栏的「时间层分布」小图——散点的横轴已经表达了同一件事，两张图重复等于没重点。

### 由此确定的三条设计原则

1. **台面是单数的。** 一旦允许两样，这个页面的问题是「A 和 B 的分子怎么叠」，那就回到了勾选清单的思路，失去了「只有一样也能开始」的立意。
2. **不给「简化视图」。** 散点就是主视图。如果它读不懂，问题是标注不够（时间轴、阈值刻度、判读句），不是图形太复杂。
3. **分子表永不完全。** 界面必须用「7 / 约 30」这种写法，而不是「它的 7 个分子」。用户一旦以为 7 是全部，后面所有推荐都会被误解为「基于全部成分」。
