# 06 · 可视化分子操作台（设计）

> 用户新增需求：「做一个可视化的化学分子操作台」。本文是它的完整设计。
> 它不是一个附属小工具，而是**产品的第二个核心界面**（与特调工作台并列）。

---

## 1. 它解决什么问题

查资料式的界面（列表 + 详情页）只能回答"这个分子是什么"。
但调酒师真正在想的是"**如果我把这两样东西放在一起、再加热/加酸/加点水，会变成什么**"。

分子操作台就是这个思考过程的**可视化实验台**：

- 分子是**可以被拿起来、移动、靠近、连接的物体**（而不是表格里的一行）。
- 靠近即反应：两个分子被拖到一起，若存在反应规则，台面立刻给出**预览**（"会生成 XX，条件是 pH<4.6"）。
- 条件是可拨的：pH、温度、时间、乙醇浓度、氧气、光照 —— 拨动就是"做实验"。
- 结果可落地：产物能一键"反查现实中怎么得到它"（哪个食材、用量多少、什么技法）。

一句话：**把"想"变成"看得见的手上操作"。**

---

## 2. 三种工作模式

台面顶部有三个模式标签，共用同一块画布，状态可延续（切模式不丢东西）。

### 模式 A · 分子工坊（Molecule Bench）

从左侧抽屉里拖分子卡到台面，自由摆放、分组、连线。

- 卡片正面：**2D 结构式**（预渲染 SVG）+ 中文名/英文名 + 风味族色条 + 一句话气味。
- 卡片背面（点击翻转）：CAS、分子式、沸点、logP、阈值、来源食材。
- **自动布局助手**：一键把台面上的分子按「风味族」聚成星团，或按「logP × 阈值」排成散点
  （直观看出"哪些分子又亲脂又低阈值=容易盖住别人"）。
- **共享子结构高亮**：选中 2 个以上分子时，共同的官能团/骨架高亮闪烁（比如两个酯都亮出 `-COO-`），
  并给一句"同族 → 感知叠加"的解释。

### 模式 B · 反应台（Reaction Bench）· 灵魂所在

把分子（或"分子 + 食材"）放到台面中央，底部**条件拨盘**开始生效。

底部控制条（四个拨盘 + 两个开关）：

| 控制 | 范围 | 默认 |
|---|---|---|
| pH | 1 – 9 | 4.5 |
| 温度 | −20 – 200 °C | 20 |
| 时间 | 0 s – 30 天（对数刻度） | 1 h |
| 乙醇浓度 | 0 – 70 % | 0 % |
| 氧气 | 开/关 | 关 |
| 光照 | 开/关 | 关 |

拖动拨盘时，台面上：
- 满足条件的反应 → 分子间浮现**发光连线 + 反应标记**，右侧读数面板出现产物卡；
- 不满足条件 → 连线变成虚线灰色，鼠标悬停显示"还差什么"（例如"需 ≥120 °C"、"需 pH<4.6"）；
- 时间拨到"几周"时，缓慢反应（酯化、氧化）才会点亮 —— **这个真实的"慢"要被做出来**，
  它恰好解释了很多调酒经验（"预调瓶放三天更好喝"）。

产物卡可以：
- 继续拖进台面 → 参与**二级反应**（例如美拉德产物再参与 Strecker 降解）；
- 右键 → "哪些食材含它" → 跳到食材库；
- 拖到"配方"槽 → 进入特调工作台作为风味目标。

### 模式 C · 映射台（Bench → Glass）

把台面上的分子组合，翻译成**现实做法**。

- 对每个目标分子，列出能提供的食材，按"浓度/成本/可得性"排序；
- 给出"要达到 3 倍阈值，需要 XX 食材约 N ml"的**估算用量**（并明确标注估算置信度）；
- 给出对应技法（浸渍/奶洗/加热/酶解/烟熏）与操作参数。

> 这一层是"从化学回到厨房"的桥。没有它，操作台就只是个漂亮的玩具。

## 4. 八条核心交互（按重要性排序）

1. **拖近即预演**：两卡距离 < 80 px 时触发"反应预演"（半透明产物虚影），松手才确认。
   距离是唯一门槛，不需要画连线——降低操作成本。
2. **条件拨盘 = 实时合法性**：每次拖动都重算可见反应集合；不可行的反应显示"差什么"，
   这比直接隐藏更有教学价值。
3. **时间必须是真的**：秒级反应（酸碱沉淀）、小时级（浸渍）、天级（酯化/氧化）分层点亮，
   用台面背景的"沙漏环"表示当前时间尺度。
4. **阈值倍数实时算**：右侧始终显示"当前分子浓度 ≈ X 倍嗅觉阈值"，用一条横向色带
   （闻不到 / 刚好可辨 / 明显 / 过强发冲）呈现。**这是把化学量化为"能不能闻到"的关键。**
5. **共享子结构高亮**：选中多个分子时高亮共同官能团，配一句"正因为都是酯，所以叠加"。
6. **产物可继续参与**：不做死胡同，产物就是新分子卡。
7. **一键"反查现实"**：任何分子 → 哪些食材有它 → 需要多少 → 用什么技法。
8. **可保存为"实验记录"**：台面状态（分子 + 位置 + 条件）存成一条记录，
   可命名、加笔记、导出 JSON，也能作为配方草稿的附件。

## 5. 视觉风格（承接 Q8 = 纸质调酒手册）

定为 **「1930 年代标本图鉴 × 实验记录本」**：

- 底色 `#F4EFE3`（旧纸），主文字 `#2B2620`（墨），强调 `#8C5A2B`（铜/焦糖），
  辅助 `#3E5C4B`（墨绿）、`#A33B2B`（朱砂，仅用于警示与反应）。
- 标题用衬线（思源宋体 / Noto Serif SC），数据用等宽（JetBrains Mono）。
- 台面是**方格纸纹理**（浅淡 5 mm 网格），分子卡像"贴上去的标本标签"，
  有极轻的纸片阴影与轻微旋转（±1°，随机），不追求科技感，追求"手作实验记录"的质感。
- 结构式用**单线黑/深棕线条**，像铜版画；风味族用色条而非大面积色块。
- 反应发生时：不是发光特效，而是**墨迹晕开 + 手写体批注**（"→ 生成香芹酮，条件：光+O₂"）。
- 动效克制：150–250 ms，缓入缓出；不做粒子、不做霓虹。

> 为什么不用暗色实验室风：长文阅读累、手机上看不清、且"暗色 + 荧光绿"是同类产品最烂大街的做法。
> 纸质质感反而与"风味分子"这种嗅觉主题更搭，也更耐看。

## 6. 反应规则表（12 条，操作台首批内容）

数据字段见 §7。`速率` 决定在哪个时间尺度点亮。

| # | 反应 | 反应物 | 条件 | 产物 / 感官变化 | 速率 | 证据 |
|---|---|---|---|---|---|---|
| R1 | 酯化 | 羧酸 + 醇 | 酸催化、≥80 °C 或数周 | 酯 + 水；"生青 → 果香" | 天–周 | 文献 |
| R2 | 酯水解 | 酯 + 水 | 碱性 pH>8，或长时间/高温 | 羧酸 + 醇；"果香消失、出现酸败/肥皂感" | 小时–天 | 文献 |
| R3 | 美拉德 | 还原糖 + 氨基酸 | ≥120 °C、低水分 | 吡嗪/呋喃/Strecker 醛；"烤面包、坚果、焦糖" | 分钟 | 文献 |
| R4 | 焦糖化 | 糖 | ≥160 °C | 呋喃类、麦芽酚、双乙酰；"焦糖、奶油、微苦" | 分钟 | 文献 |
| R5 | 萜烯氧化 | 柠檬烯 + O₂ + 光 | 常温、光照 | 香芹酮、萜烯过氧化物；"新鲜柑橘 → 陈油/塑料味" | 天 | 文献 |
| R6 | 多酚氧化褐变 | 儿茶素 + O₂（+ PPO 酶） | 常温、接触空气/切开 | 醌类聚合物；"变褐、涩感增强" | 分钟–小时 | 文献 |
| R7 | 花青素 pH 平衡 | 花青素 | pH 3 / 5 / 7 / 9 | 红 / 紫 / 蓝 / 绿色（不是生成新物质，是平衡移动） | 瞬时 | 文献 |
| R8 | 酪蛋白等电点沉淀 | 酪蛋白 + 酸 | pH ≤ 4.6 | 絮凝沉淀（吸附脂溶性香气）"就是奶洗" | 瞬时–小时 | 文献 |
| R9 | 乌佐效应 | 茴香脑 + 水 | 乙醇 < ~30%、快速加水 | 自发纳米乳液；"清澈 → 乳白云雾" | 瞬时 | 文献 |
| R10 | 酶解澄清 | 果胶 + 果胶酶 | 4–20 °C、数小时–过夜 | 半乳糖醛酸；"浑浊 → 清澈" | 小时 | 文献 |
| R11 | 铁-多酚络合 | 多酚 + Fe³⁺ | 微量铁 | 深蓝黑络合物；"变色、发暗" | 瞬时 | 文献 |
| R12 | 乙醇-水缔合 | 乙醇 + 水 | 任意 | 放热 + 体积收缩（约 −3.6% 于 50% v/v）；**影响 ABV 计算** | 瞬时 | 文献 |

> 反例也要写进去：`verdict: avoid` 的反应（R2、R5、R6、R11）在 UI 上用朱砂色，
> 并给"怎么避免"（避光、充氮、减少氧化、别用铁器）。

## 7. 数据结构

```ts
interface Reaction {
  id: string;                 // "esterification"
  name: string; nameEn: string;
  mode: "chemical" | "physical" | "equilibrium";
  reactants: {
    match: string;            // compound id | "role:carboxylic-acid" | "class:ester"
    stoich?: number;
    optional?: boolean;
  }[];
  conditions: {
    ph?: [number, number];
    tempC?: [number, number];
    timeH?: [number, number];
    ethanolPct?: [number, number];
    oxygen?: boolean;
    light?: boolean;
    enzyme?: string;
    metalIon?: string;
  };
  products: {
    match: string;            // 产物分子 id 或 "class:pyrazine"
    sensoryDelta: string;     // "生青 → 果香"
    note?: string;
  }[];
  rate: "instant" | "minutes" | "hours" | "days" | "weeks" | "negligible";
  reversible: boolean;
  verdict: "desired" | "contextual" | "avoid";
  mechanism: string;          // 一句话机理（必填，UI 直接显示）
  teaching?: string;          // 教学补充（为什么调酒师这么做）
  evidence: "literature" | "mechanism" | "consensus";
  sources?: Source[];
}

interface BenchState {          // 可保存的实验记录
  id: string;
  name?: string;
  mode: "workshop" | "reaction" | "mapping";
  nodes: { id: string; kind: "compound" | "ingredient" | "product" | "note";
           refId?: string; x: number; y: number; label?: string }[];
  edges: { from: string; to: string; reactionId?: string; label?: string }[];
  conditions: { ph: number; tempC: number; timeH: number;
                ethanolPct: number; oxygen: boolean; light: boolean };
  notes?: string;
  createdAt: string; updatedAt: string;
}
```

**阈值倍数怎么算（必须诚实）**

浓度计算需要"某食材中某分子的绝对含量（mg/L）"，这类数据文献极缺且波动巨大。
所以采用**分级估算**，并在 UI 上永远带"估算"标记：

| 等级 | 代表浓度（mg/L，水中） | 显示 |
|---|---|---|
| trace | 0.01 | "≈ 0.1× 阈值" |
| low | 0.1 | 接近阈值 |
| medium | 1 | 数倍阈值 |
| high | 10 | 强烈 |
| dominant | 100 | 过强/发冲 |

再加上"基质修正"（乙醇基质阈值通常更高，糖会压香）。
**置信度低时必须显示低置信度**，这是数据伦理问题，不是细节。

## 8. 技术方案

| 问题 | 方案 | 理由 |
|---|---|---|
| 2D 结构式 | **构建期预生成 SVG**（离线用 RDKit 批量出图，存进 JSON） | 120 个分子可控；运行时零依赖、零 WASM、秒开、可离线 |
| 兜底 | 若新增分子没图，运行时用 `smiles-drawer`（~100 KB）生成 | 允许后续扩充 |
| 台面渲染 | **DOM + SVG**，非 Canvas | 可拖拽、可无障碍、可 CSS 做纸质感；分子数 < 300 时性能足够 |
| 拖拽 | Pointer Events（一套代码兼容鼠标/触屏） | 手机优先（Q11）的要求 |
| 状态 | 单一 `BenchState`，命令式 undo/redo 栈 | 撤销是核心体验 |
| 反应求解 | 每帧只算"可见反应"（O(反应数 × 分子数)，反应数 ~50） | 无需索引优化 |
| 持久化 | IndexedDB 存实验记录 + localStorage 存偏好 | 纯本地，无后端（Q4） |
| 离线 | Vite 构建 + PWA（Service Worker） | "发给朋友双击都能用" |

**P0 最小可用版本（不追求炫）**

1. 分子卡可拖拽（含结构式、风味族色条）；
2. 两卡靠近触发反应预演（只做 R1/R3/R5/R7/R8/R9 六条）；
3. 底部 pH/温度两个拨盘 + 时间滑块；
4. 右侧读数面板：风味雷达 + 阈值倍数 + 产物卡 + 机理一句话；
5. 撤销/重做；实验记录保存。

**P1**：全部 12 条反应 + 乙醇/氧气/光照开关、映射台、"反查食材"、共享子结构高亮。
**P2**：多步反应链（美拉德 → Strecker 降解）、3D 结构（3Dmol.js）、
「结构变形实验室」（换掉酯的醇基看风味如何变化——纯教学彩蛋）。

## 9. 边界与诚实说明

- **这不是分子动力学模拟器**。不做量子化学、不预测未知反应。它是
  「规则 + 查表 + 示意动画」的知识工具。
- 反应表每条都必须有 `mechanism` 与 `evidence`，没有出处的一律标 `待验证`，
  并且不出现在"推荐"结论里。
- 结构式只是**二维骨架示意**，不标立体化学，不画电子转移（除非手绘简化箭头）。
- 产物"感官变化"是文字描述，不保证个体一致（阈值存在 10–100 倍个体差异，
  这一点必须在"关于"页写清楚）。
