# 10 香调设计（前调 · 中调 · 后调）

> 对应 `samples/05-香调设计.html`。
> 用户原话（m00485）：**「我选一个自己有的材料，然后根据化学成分先选择要保留的香型，并据此推荐其他材料：细分前调中调后调，选择完之后可以直接转到技法界面」**

---

## 1. 它解决什么问题

04「技法推荐」的前提是你已经有一批材料。但真实情况常常是：**我只有一样东西**，比如一盒草莓。
这时候要问的不是"用什么技法"，而是"**再做一杯什么样的酒，才配得上它**"。

香调设计就是补这一段：从一个主材料出发，先决定留住它的哪几层香气，再去找能补上其余层次的材料。

```
① 选主材料 → ② 选要保留的香型 → ③ 按前/中/后调补搭配 → ④ 进技法台
```

它是技法台的**第二个入口**（`我有一批材料 → 直接推荐` ｜ `我只有一样 → 先定香调`），不是新导航项。

---

## 2. 前中后调不是玄学，是三个可测量

调酒书里"前调/中调/后调"常写得像通感修辞。这里把它落到三个物理量上：

| 判据 | 决定什么 | 数据来源 |
|---|---|---|
| **挥发速率**（沸点、logP、分子量） | 多久到鼻子 —— 决定它属于前/中/后哪一层 | 沸点表 + logP + 分子量 |
| **阈值**（mg/L） | 闻不闻得到 —— 决定它是否值得出现 | 文献阈值表 |
| **浓度** | 强度、以及会不会"发冲"——同一分子低是熟果、高是香水 | 食材含量分级估算 |

于是「前/中/后」有了可计算的边界：

- **前调 0–5 min**：沸点 < 150℃ 或 logP < 2 的小分子，阈值低、扩散快（酯类、醛类）
- **中调 5–30 min**：中等极性（芳樟醇、苯乙醇、紫罗兰酮）
- **后调 30 min +**：低挥发、高 logP 或高水溶性低阈值（香兰素、呋喃酮、愈创木酚）

界面上的「挥发时间轴」就是这张表的可视化：每样材料画成一条带，宽度 = 它的香气能持续多久。
**同一个材料可以横跨多层**（草莓就是：己烯醛秒级、芳樟醇分钟级、呋喃酮小时级）。

---

## 3. 「香型（Facet）」是这一页的核心对象

用户不懂 `(Z)-3-己烯醛`，但他懂"青草味"。所以中间加一层抽象：

```
材料 → 关键分子 → 香型(Facet) → 用户选香型
```

草莓的 7 个关键分子聚成 5 个香型：

| 香型 | 代表分子 | 时间层 | 稳定性 |
|---|---|---|---|
| 熟果甜香 | 丁酸乙酯 + 呋喃酮 | 前 + 后 | 高 |
| 青绿鲜草 | (Z)-3-己烯醛 | 前 | **极低**（半衰期几分钟） |
| 花香 | 芳樟醇 | 中 | 中 |
| 焦糖奶油 | 呋喃酮 + 麦芽酚 | 后 | 需温热才明显 |
| 酸鲜 | 柠檬酸 / 苹果酸 | —（味觉） | 高 |

**用户选的是香型，不是分子。** 分子只用来解释"为什么"和算"会不会打架"。

「稳定性」这一栏是这一页最有价值的信息：它预告了下一步技法会毁掉什么。
左下角的「香型存活率」直接把话说明白——**慢煮 65℃/90 min 之后，青绿香只剩 12%**，
想要它就得换快速浸渍。**用户在选香型的时候就知道代价，而不是做完才发现。**

---

## 4. 推荐逻辑：补空的那一层

推荐不是"和草莓搭的东西"，而是**按三个时间层分别找补**：

| 关系 | 含义 | 例子 |
|---|---|---|
| **协同 synergy** | 同族分子叠加，同一方向加强 | 青柠皮的 d-柠檬烯 → 抬高果香知觉强度 |
| **对比 contrast** | 反向拉一下，制造层次 | 陈皮的苦 / 气泡的冲 / 酸的尖 |
| **托底 ground** | 低挥发、低阈值，撑住尾巴 | 香草荚的香兰素接住呋喃酮的焦糖 |

一个材料卡必须写清四件事，缺一不可：

1. 它贡献的**关键分子 + 阈值**
2. **机制**（为什么能接上，或者为什么会打架）
3. **建议用量**（不给量的建议等于没给）
4. 与主材料/已选材料的关系（协同 / 对比 / 托底）

每层最多给 3–4 个候选。**选择过载比选择不足更糟**——三层 × 4 个 = 12 个候选已经是上限。

---

## 5. 冲突检测：这一页真正防止翻车的地方

推荐之外必须主动报冲突，否则"搭配"就退化成随机组合。首版三类：

**① 同段时间抢位**
> 青柠皮与紫苏都在抢前 30 秒。两样都留，前调会挤在一起 → 紫苏减到 1 片，或上桌前再放。

**② 浓度反转**（同一个分子，过了阈值方向就变）
> 吲哚（茉莉）在 0.5 mg/L 以下是花香，以上转向粪臭。这是它最危险的地方。

**③ 乙醇压制**
> 冷熏橡木与呋喃酮同为"烤过的甜"，理论上接得上；但乙醇 > 25% 时会明显压果香 → 先算 ABV。

第 ②类是本产品最该做对的东西：**它是反直觉的、可查证的、且真的会导致一杯酒毁掉。**
一般配方 App 只会说"加茉莉很香"，不会告诉你加多了是臭的。

## 6. 数据结构

```ts
type TimeLayer = 'top' | 'heart' | 'base';

type Facet = {
  id: string;
  name: string;            // 熟果甜香
  nameEn: string;          // RIPE FRUIT
  compounds: string[];     // ['ethyl-butyrate', 'furaneol']
  timeLayer: TimeLayer[];  // 可跨层
  stability: number;       // 0–1，对温度的耐受
  note?: string;           // 需要温热才明显
};

type Pairing = {
  a: string;               // ingredient | facet id
  b: string;
  relation: 'synergy' | 'contrast' | 'ground';
  mechanism: string;       // 必填，禁止空话
  dosage?: { amount: number; unit: string; note?: string };
  conflict?: { type: 'same-window' | 'inversion' | 'ethanol-mask'; detail: string; fix: string };
  evidence: '文献' | '机理' | '共识' | '待验';
};
```

`Facet` 是**派生对象**：由 `Compound` 的沸点/logP/阈值自动聚类生成初稿，人工校对。
不能手工维护——否则 60 个食材 × 5–8 个香型 = 三四百条，改不动。

---

## 7. 与技法台、配方台的衔接

| 出口 | 带过去什么 |
|---|---|
| **去技法台** | 主材料 + 已选搭配（含用量）+ 目标（更香）→ 走 04 的推荐流程 |
| **去配方台** | 同上，直接进配比（跳过技法） |
| **存为"香调方案"** | 可复用：下次同样的主材料，直接调出来 |

衔接的关键：**选完搭配不是终点，而是技法的输入。**
所以香调页的按钮写「带着这个构成去技法 →」，而不是「保存」。

---

## 8. 三期

- **P0**：单主材料，5 个香型可选，三层各 2 个候选，三类冲突检测
- **P1**：多主材料（两个主材料互相补层）、存活率按技法实时联动
- **P2**：香调方案的复用与分享；从成品酒的品鉴记录反推香调结构

## 12. v0.9 修订：符号表、换一换、专业模式（依据 m00542 答复）

### 12.1 香型符号表（全站统一）

| 香型 | Facet | 颜色 | 图形 | 代表分子 |
|---|---|---|---|---|
| 熟果甜香 | ripe-fruit | `#B4693A` | `●` | 丁酸乙酯、呋喃酮、乙酸己酯 |
| 青绿鲜草 | green-leaf | `#4F7A46` | `▲` | (Z)-3-己烯醛、紫苏醛 |
| 花香 | floral | `#8A6E92` | `❀` | 芳樟醇、β-紫罗兰酮、香叶醇 |
| 焦糖奶油 | caramel | `#7B5230` | `◆` | 麦芽酚、香兰素、愈创木酚 |
| 酸鲜 | sour-fresh | `#B9A03C` | `✦` | 柠檬酸、苹果酸 |

**空心 `◇`** 表示"无对应香型的对照/物理/触觉项"（薄荷的 TRPM8 冷感、CO₂ 物理前调、陈皮的苦）。
它们不贡献香气但改变知觉，必须和香型区分开，所以用空心而非某个色。

双编码规则：**形状承担信息，颜色只做加速**。色觉障碍者仍可按形状区分；
打印成黑白配方卡时形状仍是唯一可依赖的区分手段。

### 12.2 换一换

位置：前 / 中 / 后 每列 header 右侧。一次替换该层中**未选中**的候选。

为什么必须有：每层 4 条候选是演示规模，真实用户冰箱里的东西比数据库更杂。
"这些都不是我想要的"如果没有出口，整个流程就断在这一步。

前提：每层候选池 ≥ 10 条。这条直接改变了数据量的下限——
原先按"每层 4 条 × 3 层 = 12 条材料"估算，现在需要 **30 条以上的备选材料**（连同各自的分子与阈值）。

### 12.3 专业模式

| | 关闭（默认） | 开启 |
|---|---|---|
| 香型卡 | 香型名 + 稳定性 | 追加分子名 |
| 材料卡 | 机制说明 + 用量 | 追加 阈值 / logP / 沸点 |
| 关键分子表 | 中文名 + 前/中/后 | 追加 English / CAS / 阈值 |
| 冲突提示 | 保留 | 保留（加数值依据） |

默认关闭的原因：分子名对家庭用户是噪音，对专业用户是可信度。
一个开关同时服务两类人，比做两套界面便宜，也比隐藏信息诚实。

### 12.4 这轮改完之后，数据清单的字段最终确定

每个分子必须有：`id / nameZh / nameEn / cas? / formula / bpC / logP / thresholdMgL / timeLayer / facets[] / dict (香型描述词)`

每个材料必须有：`id / nameZh / nameEn / category / phase (solid/liquid) / waterPct / ph / sugarG100 / acidG100 / pectinPct / compounds[{id, level}] / roles[] / techniques[]`
