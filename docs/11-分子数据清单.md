# 11 · 分子数据清单 v0.1（120 个风味分子）

> 数据文件：`data/compounds.json`（唯一事实来源）
> 渲染脚本：`scripts/build-compendium.mjs`（`node scripts/build-compendium.mjs` 生成 `samples/06-分子图鉴.html`）
> 图鉴截图：`samples/06-分子图鉴.png`

## 1. 为什么先做分子而不是食材

食材可以增删，分子是地基。上面四个界面（技法推荐 / 香调设计 / 配方台 / 分子台）全部读同一张分子表：

- 香调设计：`facets` + `tLayer` → 前中后三列
- 技法推荐：`from`（哪些食材含它）+ 技法参数 → 存活率
- 配方台：`odorMgL` → 阈值倍数 → "闻不到 / 刚好 / 明显发冲"
- 分子台：`formula` + `bpC` + `logP` → 反应条件与挥发速度

**分子表的字段一错，四个界面全错。** 所以这一版先把字段做全，再谈覆盖多少。

## 6. 这一版我明确没做好的地方

1. **CAS 号需批量核对**。多数是通识值，但 120 条里我至少有几条不能保证。建议用 PubChem 按 `en` 名字批量查一遍再回填，不要信任我的记忆。
2. **阈值精度是"数量级"级别**。同一物质不同文献差 2–10 倍是常态；`est` 那 72 条更粗。UI 上必须永远显示"估算"，不能给三位有效数字。
3. **时间层是推的，不是测的**。按 bp + logP + 阈值三条规则推，规则写在下节。真实感知还受基质（糖、乙醇、脂肪）影响，误差可能整整一个层。
4. **覆盖偏萜烯与酯类**，因为我熟这两类。**硫化物只收录了 3 个**（二甲基硫醚、糠硫醇、甲硫基丙醛），实际硫化物是风味里最猛的一类（洋葱、蒜、热带水果、咖啡），这块需要补。
5. **完全没有脂香/海潮/矿物类**。"海风感"这类近年流行词目前没有分子支撑，我不硬造。

## 7. 时间层的推算规则（供你审）

```
if 阈值 ≤ 5e-4 且 bpC ≥ 240  → base（低阈值慢挥发，长尾）
else if bpC < 160 或 logP < 2  → top
else if bpC ≥ 240              → base
else                            → heart
```
阈值极低的物质即使挥发慢也该算"中"，因为它一出现就被闻到；这条规则放在第一条，优先于沸点判断。

## 13. v1.1 扩充：硫香与无机物（依据 m00648 答复）

用户的四个答复：① 不只有机分子，重要无机物也要 ② 硫香等更多类别放最后、做成「展开」 ③ 60% 估算可接受 ④ CAS 要核对 ⑤ 先定分子表，60 食材稍后。

### 13.1 新增两个「扩展族」，不进主表

| 族 | 符号 | 色 | 条数 | 为什么不算主香族 |
|---|---|---|---|---|
| 硫香 SULFUR | `✸` | `#6E6B23` | 8 | 绝大多数是**缺陷**而非设计目标：还原味、烂菜、洋葱 |
| 矿物 · 刺鼻 MINERAL | `✱` | `#6E7A7A` | 15 | 一半根本**不是气味**：盐、氧气、离子、N₂O |

主香族 12 个 × 120 条保持不变，上面这两族 23 条在页尾折叠区，默认收起。

**为什么不给它们单独做一套界面**：调酒时你不会「想加点硫化氢」。这些分子的作用方式不同——
硫香是**避坑清单**，矿物是**约束条件**。把它们混进 12 族会污染"按香型选材料"这个动作。

### 13.2 新增字段

- `kind: "inorganic"`：标记无机物。前端据此换一种图标与说明语气（不当成风味分子来展示）。
- 无气味者一律 `odorMgL: null` + `tLayer: "none"`，图鉴里显示「—」，不硬编一个数字。

### 13.3 硫香 8 条（全部是「出现了就是出事」系列）

硫化氢（臭鸡蛋，有习服性）、甲硫醇（瓶内还原）、二甲基二硫醚、二甲基三硫醚、甲硫基丙醇、
3-甲硫基丙酸乙酯（这条是**正面**的：菠萝香）、硫代薄荷酮（西柚/黑加仑）、二氧化硫。

> 其中只有 3-甲硫基丙酸乙酯与硫代薄荷酮是"好的"。硫香族的用处是**辨认**：
> 闻到它时你知道该换气、该换酒，或该换一个铜壶。

### 13.4 矿物 15 条

可闻的 5 条：氨、氯/次氯酸、臭氧、二氧化硫、硫化氢（已在前一族）。
不可闻但有决定性的 13 条：CO₂、NaCl、KCl、CaCl₂、MgSO₄、NaHCO₃、Ca(OH)₂、磷酸、Fe³⁺、Cu²⁺、O₂、N₂O。

**这些才是"化学"最硬的部分**：盐抑制苦味、钙带来涩、铁与多酚络合变黑、氧气毁掉青绿香。
它们不贡献香气，但决定一杯酒能不能成立。

### 13.5 CAS 核对

`scripts/fetch-cas.mjs` 逐条查 PubChem：
1. `compound/name/{英文名}/property/MolecularFormula` → 得到 CID 与分子式，与本地 `formula` 对比（`formulaMatch`）
2. `compound/cid/{cid}/synonyms` → 用正则 `/^\d{2,7}-\d{2}-\d$/` 取 CAS

结果落在 `data/cas-lookup.json`。**分子式对不上的条目视为可疑**，需人工判断是命名歧义还是我写错了。

### 13.6 已知缺口（下一版补）

- 脂香/海潮（紫菜、贝类、金属感）没有独立族，暂时散在 `dairy` 与 `mineral`
- 吡嗪类只收了 5 条，烘焙类实际远不止
- 硫香缺"蒜素/二烯丙基二硫"这类含硫蔬菜分子
- 非挥发物（单宁、花青素、果胶、酪蛋白）**仍不在本表**，它们属于「结构分子」，
  与香调无关，应另开一张表（P1）

### 13.7 CAS 核对结果（2026-11-10 完成）

`node scripts/fetch-cas.mjs` → `node scripts/merge-cas.mjs` 两段跑完，**143 条全部在 PubChem 找到**：

| 项 | 数量 |
|---|---|
| 查到 CAS | 143 / 143 |
| 分子式与 PubChem 一致 | 133 |
| 分子式写法不同（Hill 序） | 10 |
| 本地 CAS 与 PubChem 首选值不同 | 5 |

**分子式 10 条"不符"全是我用惯用写法、PubChem 用 Hill 序**：
`SO2`/`O2S`、`NaCl`/`ClNa`、`KCl`/`ClK`、`MgSO4`/`MgO4S`、`NaHCO3`/`CHNaO3`、
`Ca(OH)2`/`CaH2O2`、`H3PO4`/`H3O4P`、`Fe3+`/`Fe+3`、`Cu2+`/`Cu+2`、`NH3`/`H3N`。
**决定保留人类惯用写法**——写 `NaHCO3` 的人比写 `CHNaO3` 的多，界面不是论文附录。

**5 条 CAS 差异**（已写入 `data/cas-review.md`，未自动覆盖）：

| 分子 | 本地 | PubChem 首选 |
|---|---|---|
| 反-2-壬烯醛 | 18829-56-6 | 2463-53-8 |
| 芳樟醇氧化物 | 60047-17-8 | 1365-19-1 |
| 反式茴香脑 | 4180-23-8 | 104-46-1 |
| 薄荷酮 | 10458-14-7 | 89-80-5 |
| 2-乙酰基吡嗪 | 1122-62-9 | 22047-25-2 |

原因是 **PubChem 取 synonyms 里第一个匹配项**，异构体与通用条目混在一起：
本地值多为更具体的异构体号（如反式茴香脑 4180-23-8 是 (E)-体，104-46-1 是通用 anethole）。
所以合并脚本的策略是「**只填空、不覆盖，差异留档待人工确认**」。

铁离子 `20074-52-6`、铜离子 `15158-11-9` 是原先空着、这次补上的。

> 这一步的意义不是"证明了数据对"，而是**把不确定性从"我记得"变成"可复查的清单"**。
