## 1 · 为什么要重做

01 是在**只有设计概念、没有数据**的时候画的。它的数字（ABV 16.2%、糖 12.0 g/100mL、总酸 6.8 g/L）是「看起来合理」的示意值，不是任何一张表算得出的。

四张表落地之后，这些数字对不上：

| 项 | 01 的示意值 | 按表 A/B 重算 | 差在哪 |
|---|---|---|---|
| ABV | 16.2% | 10.0% | 01 忽略了冰融稀释，也把 45 ml 烈酒当成了不稀释 |
| 糖 | 12.0 g/100mL | 3.7 g/100mL | 01 把「蜂蜜糖浆 15 ml」当成糖浆本身，没按 55 g/100mL 折算 |
| 总酸 | 6.8 g/L | 4.5 g/L | 01 按「Sour 典型值」写，没按青柠 6 g/100mL 折算 |
| pH | 4.2 | 3.2 | 同上，且 01 的 pH 与总酸不自洽 |

**结论不是「调数字让它好看」，而是让页面服从表。** 这杯因此变得「偏干、偏轻」——这是真实结果。

## 2 · 新结构与每一块的来源

```
顶栏  推荐 · 技法 · 配方 · 分子 · 资料
├─ 左栏
│   ├─ 分液层高球杯（5 层，按 ml 比例）
│   ├─ 5 条比例滑块
│   ├─ 楷体批注（唯一一处手写）
│   ├─ 比例判读     ← 与同骨架的典型区间比
│   ├─ 替换与变体   ← 同骨架换材料
│   └─ 技法建议     ← 表 T（20 技法）
└─ 右栏
    ├─ 五项读数     ← 表 B（ABV/密度/气泡）+ 表 A（糖/酸/pH）+ 冰融模型
    ├─ 风味轮廓 8 轴 ← 143 条挥发分子（阈值 + 含量分级）
    ├─ 风味族 5 条   ← 12 香族的前 5 名
    ├─ 结构判读     ← 表 C（53 条不挥发分子）
    ├─ 交互提示     ← 规则库（协同 / 抑制 / 掩蔽 / 稀释）
    └─ 来源条       ← 逐项标注出处
```

## 3 · 「结构判读」为什么值得单独一块

这是表 C 第一次进界面，也是这版和 01 最本质的区别。六行都回答一个「闻不到但会毁掉一杯」的问题：

| 行 | 回答什么 | 这杯的结论 |
|---|---|---|
| 浑浊 | 会不会浑，为什么 | 低 —— 纤维素被滤掉，青柠果肉会沉底 |
| 可澄清性 | 能不能澄清、用什么 | 高 —— 果胶 0.2%、蛋白极低，果胶酶 30 min 可透亮，但**不建议** |
| pH 敏感色 | 颜色会不会变 | 无花青素，pH 3.2 不影响；加洛神花要重算 |
| 蛋白 × 单宁 | 会不会起絮 | 都近 0 —— **这也是它不能做奶洗的原因** |
| 油脂 | 哪些分子进不来 | 无油相，辣椒素/姜黄素进不来 |
| 气泡 | 能撑多久 | 2.6 vol，4℃ 罐装可到 3.2 |

关键设计：**「可澄清性：高」但结论写「不建议」**。能力与建议分开——计算告诉你做得到，判断告诉你别做。

## 4 · 数据流（代码阶段的接口）

```
BenchState{ lines: [{ingredientId | baseId, ml}] , iceMeltPct, glassId }
        │
        ├─ Calc.mix()      → ABV / 糖 / 总酸 / pH / 体积 / 密度
        ├─ Calc.profile()  → 8 轴风味（按分子阈值加权，不按食材量）
        ├─ Calc.structure()→ 浑浊 / 可澄清 / pH 色 / 蛋白单宁 / 油脂 / 气泡
        └─ Solver.interact() → 规则命中，按影响排序
```

`Calc.profile()` 的权重规则（写进代码前要实现）：

1. 每个食材的 `aroma[]` 给 `level ∈ {dominant 3, high 2, mid 1, low 0.5}`
2. 贡献 = `level × ml / 参考量`
3. 分子贡献 → 轴值：`轴 += w(分子, 轴) × 贡献`，`w` 由香族与分子类别决定
4. 轴值 clamp 到 0–5，再与「阈值可辨倍数」对照给人话（闻不到 / 刚好 / 明显 / 过头）

## 5 · 已知问题（留给手机版与工程阶段）

- **滑块是静态的**：样张里的读数是手写固定的，改滑块不会重算。真实交互要等引擎。
- **杯子的矢量是写死的坐标**：换杯型（马天尼 / 古典 / 高球）需要三套 SVG，或用参数化路径。
- **风味族的「—」两行**：只有 5 个族有贡献时补空行对齐，工程阶段应改为「只显示有贡献的族」。
- **表 C 只覆盖了这杯的 6 个判读点**：奶洗、球化、油洗各需要自己的判读集，没做。
- **没有历史 / 撤销**：`BenchState` 的 undo 栈还没设计。
