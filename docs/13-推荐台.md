# 13 · 推荐台：从「我有什么」到「做哪一杯」

> 版本 v1.3 · 2026-11-10
> 样张：`samples/09-推荐台.html`

## 1. 为什么要有这一页

前面做了两张表（表 A 植物性食材 80 条、表 B 基底液体 32 条）和两张入口（04 材料→技法、05 单材料→香调）。但用户最初的需求其实是最朴素的一句：

> 列出我有的蔬果香料之类的食材来推荐组合还有做法。

那就是**整杯**，不是技法。技法回答「怎么处理草莓」，推荐台回答「今晚喝什么」。两者不能互相替代：

| | 04 技法推荐 | 09 推荐台 |
|---|---|---|
| 输入 | 一批材料 + 一个目标（更香/更清） | 一批材料 + 一种心情（清爽/浓郁） |
| 输出 | 一条技法 + 参数 | 3–5 杯完整配方 |
| 单位 | 一个备料（Prep） | 一杯酒 |
| 终点 | 送进技法工作台拨参数 | 送进配方台调比例 |

## 2. 三段式

```
① 选材料            ② 推荐组合                  ③ 做法
蔬果香料 / 酒与气泡   3–5 张卡：配比·做法·为什么·风险   展开全卡 / 送进配方台
```

左栏四个块：**我的蔬果香料**（从表 A 勾，带科属符号）、**我的酒与气泡**（从表 B 勾，带 ABV）、**我想喝**（清爽/浓郁/酸甜/苦烈/温暖）、**限制**（都行/无酒精/<3 分钟/不用摇）。

底部的统计是这一页的诚实声明：

> 8 样材料 · 4 支基底 · 可组 **27** 种搭配，其中 **3** 种值得试
> 已排除 14 种：缺酸 / 缺甜 / 两种香气互相抵消 / 用量会超过 6 个材料

**不展示「27 种」而展示「3 种」**，并且把排除理由写出来——这是和「AI 随便给你编一个配方」的分界线。

## 3. 方案卡六行

| 行 | 内容 | 为什么必须有 |
|---|---|---|
| 配比 | 材料 + 毫升数，固定项标绿 | 没有数字就只是灵感，不能复现 |
| 做法 | 3 步，每步一个动作 | 家庭用户需要的是「先做什么」 |
| 为什么 | 点出 1–2 个关键分子 + 一个机理 | 这是本产品的差异化，不可省 |
| 风险 | 朱砂色，一条具体的翻车点 | 不说风险 = 不可信 |
| 分子 | 三个关键分子 + 族属符号 | 与分子图鉴互通，可点进去 |
| 替代 | 三组「A → B（代价）」 | 家里缺一样东西时不用整杯放弃 |

左栏放编号、中文名、英文副名、骨架标签（Highball / Sour / Built）、ABV 与成品体积。

## 4. 引擎（与 ADR-012 一致，复用同一个 Engine）

```
DataStore → RoleMatcher → RecipeComposer → Calc → Explainer
```

1. **RoleMatcher**：把勾选的每样材料贴上角色标签（酸源 / 甜源 / 香气主体 / 溶剂 / 稀释 / 质地）。表 A 的 `actives`、表 B 的 `role` 直接喂进来。
2. **RecipeComposer**：20 个骨架里挑能填满的（Sour 要酸+甜+基酒；Highball 要基酒+稀释+香气主体；Built 只要基酒+调味）。
3. **Calc**：复用配方台的算法算 ABV / 糖 / 酸 / 体积 / 稀释。
4. **Explainer**：为每杯生成「为什么 + 风险 + 替代」，缺任一项则该杯不展示（同 ADR-005：不评判，只解释）。

五维打分沿用 ADR 里的定义：**覆盖度 40% / 协同 25% / 平衡 20% / 新颖度 10% / 简易度 5%**。

## 5. 「为什么只有三杯」

页面底部专门留了一块，写清楚被排除的原因：

- **× 缺酸**：甜味材料 5 样、酸只有 1 样，撑不起第二杯 Sour
- **× 互相抵消**：薄荷与罗勒同属辛香草本，同杯会互相盖，只能二选一
- **× 材料超标**：超过 6 样就变成「什么都有一点」，家里记不住、重复不出来
- **✓ 剩下三杯各占一个骨架**：Highball 清爽 / Sour 酸甜 / Built 温暖，互不重复

## 6. 与香调设计（05）的关系

05 是「我只有一样材料」时的深挖路径：先定香型 → 再补前中后调 → 再去技法。
09 是「我有一堆材料」时的下单路径：直接出杯。

两条路都可以走到 03 技法工作台，但 09 多了一个出口：**直接送进配方台调比例**。

## 7. 待确认

1. **一次给 3 杯还是 5 杯？** 3 杯能一屏看完，5 杯需要滚动。
2. **「缺什么」要不要单独提示？** 现在的做法是「替代」行里写，而不是单独说「你缺薄荷」。
3. **排除理由的颗粒度**：现在写 3 条，实际引擎会算 14 条，是否要「展开看全部 14 条被排除的」。

## 8. v1.4 修订（用户拍板后）

用户 m00981（原文）：「1五条，2要，3不要，结构分子表可以做」

| 问题 | 结论 | 落地 |
|---|---|---|
| 一次给几杯 | **5 杯** | 右区改为 2 列网格，5 张卡 + 第 6 格放「为什么只有五杯」 |
| 「缺什么」是否单独提示 | **要** | 每卡新增 `缺什么` 行：`✓ 不缺`（绿）或 `× 缺 X，用 Y 代替`（红） |
| 排除理由是否可展开 | **不要** | 不做「看全部 14 条」入口，只保留页尾 4–5 条结论 |

**卡片结构从六行变七行**：配比 / 做法 / 为什么 / 风险 / **缺什么** / 替代 / **读数**（ABV·糖·总酸·成品·稀释）。

五杯落到五个不同骨架，互不重复：

| No. | 酒 | 骨架 | ABV |
|---|---|---|---|
| 01 | 黄瓜薄荷高球 | Highball | 12.4% |
| 02 | 草莓桂花酸 | Sour | 14.8% |
| 03 | 陈皮黑胡椒梅酒 | Built | 7.2% |
| 04 | 罗勒青柠金菲士 | Fizz | 11.6% |
| 05 | 草莓罗勒气泡 | Mocktail | 0% |

**第 05 杯是刻意放的无酒精**：它证明「同一批材料、不勾任何酒」也能出方案，与 ADR-009（无酒精是独立维度）一致。

**缺什么这一行的写法**（这是最容易写成废话的一行）：

- 01 `✓ 不缺。想更干就把苏打换成汤力水（多一分奎宁苦）。`
- 02 `× 没桂花糖浆：蜂蜜糖浆 10 ml + 干桂花 1 g 现浸 10 min，可替。`
- 04 `× 只有干罗勒做不了这杯——干叶只有稻草味，不出丁香酚。`

**要区分两种「缺」**：一种能替代（02），一种不能替代、必须劝退（04）。后者比前者重要。
