# 18 · 资料库（v1.11）

> 样张：`samples/15-资料库.html`（1440×900）
> 这是五个区里唯一**按数据类型**分区的地方（其余四区按任务分，见 ADR-011），因为它的用途是「查」，不是「做」。

## 1 · 它在这套东西里的位置

其它四个区都是「我要做一杯」，资料库是「我想搞明白一件事」。

它同时承担三件活：

1. **词典**：一个名字 → 它是什么、多少、什么时候闻得到、在哪出现。
2. **内链枢纽**：推荐台说「同系叠加」、配方台说「蛋白×单宁 无」、技法台说「果胶酶 40–50℃」，这些词都该点得进来。
3. **可信度锚点**：四个做酒的页面都在给结论，只有这里有出处（阈值、CAS、沸点、证据等级）。

## 2 · 三段结构

```
搜索（顶，永远在）
   ↓
五类索引 + 12 香族 + 4 时间层（左，可叠加筛选）
   ↓
列表（中，一行一条，可扫）
   ↓
详情（右，选中项的完整档案 + 内链出口）
```

**为什么搜索放在最顶而不是藏进导航**：用户来这里十次有九次是带着一个词来的（「丁酸」），不是来浏览的。所以搜索框占一整行，热门词和「最近看过」在旁边。

## 3 · 五个设计决定

**① 列表和详情同屏。** 桌面 1440 下，左边一行条目的信息量足够扫，右边详情足够读，不需要点进去再退出来。手机上会退化成「列表 → 详情页」两级（见 docs/16 的手机原则）。

**② 一行里放什么，按「扫的时候要比较什么」定。**
`色点 | 名字+英文 | 阈值 | 时间层 | 香族 | 出现在哪些食材 | 相关技法`

- 阈值放第三列，因为它是**同族内排序的唯一可靠依据**。
- 「出现在」放倒数第二，因为用户的真实问题是「我手上这个有没有」。
- 技法号放最后，是跳转入口，不是阅读内容。

**③ 阈值必须配一个人话参照。** 详情里写：

> 阈值 0.001 mg/L ＝ **1 吨水里放 1 克就能闻到**

没有这句，`0.001` 只是一个数字。

**④ 「容易搞混」是一条独立区块。** 化学里最常出错的是**差一个字的两个东西**：

| | | 差别 |
|---|---|---|
| 丁酸 | 丁酸乙酯 | 酸味 / 果香 |
| 芳樟醇 | 芳樟醇氧化物 | 花香 / 陈味 |
| 柠檬烯 | 柠檬烯氧化物 | 鲜柑橘 / 松节油 |

第三条尤其重要——**柠檬烯氧化成柠檬烯氧化物，是「放坏的柑橘」和「新鲜的柑橘」之间那一步**，第三条表（表 C）里就有它的反应。

**⑤ 配对段现在明确标「暂为示意」。** 因为 `data/pairs.json` 还是 0 条。宁可写「需要配对表 · 暂为示意」，也不要让用户以为那三条是系统算出来的。

## 4 · 内链矩阵

任何一个名字都必须能点。这张表是「点了去哪」的全部情况：

| 从 | 到 | 到什么程度 |
|---|---|---|
| 分子 | 食材 | 列表（哪些食材里有它，标主角/配角） |
| 分子 | 技法 | 标签（哪些技法影响它：T1 慢煮 / T5 旋蒸…） |
| 分子 | 反应 | 参与的反应（表 C 的 R 系列） |
| 食材 | 分子 | 主角分子（3–7 个）+ 「7 / 约 30」的诚实计数 |
| 食材 | 技法 | 适用技法（T1/T3/T4…） |
| 技法 | 分子 | 它改变了哪些分子（萃取完成度、香气保留） |
| 反应 | 分子 | 反应物 + 产物 |
| 任何 | 配方 / 推荐 | 「加到配方里」「在分子台打开」两个出口 |

## 5 · 数据现状

| 类 | 条数 | 状态 |
|---|---|---|
| 食材 | 80 | ✅ 全字段 |
| 风味分子 | 143 | ✅ 含 CAS / 阈值 / 时间层 / 香族 |
| 结构分子 | 53 | ✅ 含 sol / tox / 酶 |
| 技法 | 20 | ✅ 参数 + 阶段 + 失败模式 |
| 反应 | 12 | ⚠️ 只在 docs/06 里写，**还没有 JSON** |
| 配对 | 0 | ❌ 未开始 |

所以资料库现在能查前四类，**第五类（反应）点了会空**。要么先补 `data/reactions.json`，要么在界面上把反应标成「即将上线」。
