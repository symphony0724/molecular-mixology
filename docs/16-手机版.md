# 16 · 手机版布局（v1.8）

> 样张：`samples/12-配方台-手机.html`（390×844）、`samples/13-推荐台-手机.html`（390×844）
> 基准设备：390×844（iPhone 14 / 15 逻辑尺寸）；渲染 3× 出图

## 1 · 手机不是把桌面缩小

三条硬约束先立住，再做版式：

| 约束 | 含义 | 违反的后果 |
|---|---|---|
| 一屏一事 | 一屏只回答一个问题 | 用户在手机上「找不到重点」，直接关掉 |
| 手指优先 | 可点区域 ≥ 40×40 px，滑块拇指 ≥ 18 px | 点不中，或者点错滑块改掉配方 |
| 滚动不隐藏操作 | 主操作固定在底部，永不滚走 | 改完配方找不到「保存」 |

## 2 · 桌面 → 手机的五个转换

| 桌面 | 手机 | 为什么 |
|---|---|---|
| 顶栏五个导航 + 搜索 + 酒柜 + 配方本 | 标题栏（品牌 + 搜索 + ☰）+ 一行五页签 | 桌面顶栏在手机上会挤成两行 |
| 左栏杯图 + 右栏读数（并排） | 杯图缩到 92 px 宽，读数改成 **3×2 网格**贴在右侧 | 两者本来就要一起看，竖排会切断因果 |
| 读数 5 项横排 | 3×2 网格，字号 14 px 等宽 | 5 项横排在 390 px 下每格只有 60 px，数字会换行 |
| 结构判读 / 交互 / 替换 / 技法 四块平铺 | **折叠面板**：结构判读默认展开，其余三条收成一行（带条数徽标） | 手机上四块平铺 = 必须先滑 3 屏才能到配料 |
| 底部工具条（4 个按钮） | 固定底栏只留 2 个主操作（存进配方本 / 导出配方卡） | 次操作进 ☰ 或折叠区 |

## 3 · 配方台（12）：为什么「结构判读」默认展开

四块里只有它默认展开，因为它是**这杯能不能成立**的判断（会浑、会不会起絮、颜色变不变），而交互提示、替换、技法都是「可以做，但不做也能喝」。手机上第一屏的信息配额有限，给「否决项」而不是「加分项」。

气泡那一行从结构判读里删掉了——右上角读数已经有「气泡 2.6 vol」，同一屏不重复两次。

## 4 · 推荐台（13）：为什么先给材料、后给口味

桌面版左栏是「材料 → 酒 → 口味 → 限制」四段堆叠；手机上如果照搬，用户要滑过 8 个 chip 才能看到「清爽/浓郁」的选择，而且选完口味后结果在更下面——改了看不见。

所以手机版把「我想喝」紧贴在两个 chip 组下面，并用 `按此排序` 提示「改这一行，下面的卡片会重排」，让因果关系在**同一屏内闭合**。

卡片只展开前两张（每张约 250 px 高），第三张起收成一行灰字「还有 3 杯：…」。理由：手机上 5 张全展开 = 1300 px，等于必须滑 2 屏才能比较，还不如先给两杯具体的。

## 5 · 触控细节

- 滑块 `height:3px`，但 `input` 的拇指由浏览器原生渲染（`accent-color: var(--copper)`），在 iOS/Android 上实际触摸区约 28 px——样张里看起来细，实际能点中。
- 折叠面板用整行 `<div class="ac">` 作点击区（高 34 px），不是小三角。
- 底栏 `box-shadow` 向上投 14 px 的淡阴影，暗示「下面还有内容」。
- 页面 `overflow:hidden`：样张是单屏静态图，**真实实现必须是 `overflow-y:auto` + `position:sticky` 底栏**。

## 6 · 已知问题

- **杯图被压扁**：手机版用 `preserveAspectRatio="none"` 把 150×470 的杯体压到 92×168，冰块的方形变成扁矩形。工程阶段应该做两套路径（竖版/方版），不要靠拉伸。
- **没有横屏方案**：390×844 是唯一目标尺寸，横屏与平板未设计。
- **折叠状态不记忆**：真实产品需要记住用户上次展开的是哪一块。
- **底栏「只看无酒精」放错了位置**：它是筛选器，不该和「换一批」并列；应该做成顶部的开关（和桌面的「专业模式」同一个位置）。
