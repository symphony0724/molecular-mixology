## 2 · 这一版真的在算什么

改任一滑块，下面全套重算：

| 读数 | 算法 | 诚实标注 |
|---|---|---|
| ABV | 乙醇质量 / 0.789 → 体积，再除以**收缩后**总体积 | 收缩按乙醇-水体积收缩表插值（R12） |
| 糖 g/100mL | Σ(体积×糖 g/100mL 或 质量×糖 g/100g) / 成品体积 | 全糖当量，不分单糖双糖 |
| 总酸 g/L | Σ(酸) / 成品体积，以柠檬酸计 | 不分乳酸/苹果酸/酒石酸 |
| pH | 原料 pH 的体积加权 H⁺ 与有机酸解离估计取**几何平均** | 估算；下限钳到 2.6；缓冲体系没建模 |
| 成品体积 | 入杯量 + 冰融（可选 20%）− 收缩 | 冰融按固定 20%，没有按时间积分 |
| 质量 | Σ(体积×密度 / 质量) | 果汁密度统一按 1.02 |

**风味轮廓 8 轴**：甜/酸 按糖酸读数线性映射；香 由食材的香气分子按「阈值越低越冒头」加权；苦/鲜/辛/收敛 从 `actives` 文本里匹配关键词；醇厚 由 ABV + 糖 + 乳脂/果胶。**全是 0–5 的估算，不是感官实测。**

**配方结构判读**：按角色判骨架（Highball / Sour / Built / Old Fashioned 型 / Mocktail），列出六件角色的有无、三段时间层的分子计数，缺什么直接写出来。

**做法**：由结构生成，不是模板套话——有气泡就走直调（永不摇），有乳就走静置过滤，有酸才摇。

**交互提示**：9 条规则，按影响排序取前 5。每条带机制说明和证据等级（文献/机理/共识）。例：乙醇 > 25% 压果香、糖 > 12 压香、脂肪掩蔽辣椒素、CO₂ 抬酸感、pH < 4.6 到酪蛋白等电点、单宁+蛋白互相拖、冰融稀释、糖酸比落在 Sour 区间、高度酒「先烧后香」。

## 4 · 跑起来踩到的坑（给以后）

1. **pnpm 在本机装不出可用的 node_modules**：默认 isolated 布局创建的是坏 junction（target 带 `Global\` 前缀），`picomatch` 之类解析不到。必须：
   ```
   pnpm install --prod=false --ignore-scripts --store-dir <ASCII路径> --config.node-linker=hoisted
   ```
2. `pnpm run` 的所有脚本都会失败，因为子进程里没有 `node`。**要直接用绝对路径调** `node node_modules/vite/bin/vite.js`。
3. **esbuild 会 spawn 子进程，在 DSH 沙箱里报 `spawn EPERM`**——启动 dev / build 必须放宽沙箱（danger-full-access）。
4. pnpm 11 的 `pnpm.onlyBuiltDependencies` 字段已废弃，要写进 `pnpm-workspace.yaml`；本项目直接 `--ignore-scripts` 绕过。
