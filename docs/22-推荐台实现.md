# 22 · 推荐台（测试版实现，v0.2）

> 代码：`src/engine/compose.ts` + `src/views/RecommendView.tsx`
> 入口：页签第一格「推荐 RECOMMEND」，也是默认页。

## 1 · 它在干什么

用户勾手里有的东西（蔬果香料 / 酒与气泡），选一个「想喝」的调性，得到 5 张卡。每张卡说清楚：**什么骨架、什么配比、为什么是这几样、缺什么、有什么风险、五项分数**，然后一键送进配方台。

和样张（`samples/09-推荐台.html`）的差别：样张是画出来的，这里是**算出来的**——所有数字都来自 `data/` 里那五张表。

## 2 · 引擎链路

```
输入（勾选的 id + mood）
  ↓ 选主料：优先蔬果，按风味族得分
  ↓ 套模板：5 套骨架，各自有「需要的角色 → ml」
  ↓ 缺角色就补位（PANTRY），并记进 borrowed
  ↓ computeMix / judgeStructure / interactions / aromaProfile（复用配方台那套）
  ↓ 五维打分 + mood 偏置
  ↓ 出卡（why / risk / missing / method）
```

### 五套模板

| 骨架 | 配比（ml/g） | 目标区间 |
|---|---|---|
| Highball 高球 | 酒 45 / 酸 20 / 甜 12 / 气泡 60 | ABV 8–14 · 糖 1–5 · 酸 3–7 |
| Sour 酸 | 酒 50 / 酸 20 / 甜 15 | ABV 12–18 · 糖 6–12 · 酸 4–8 |
| Fizz 菲士 | 酒 45 / 酸 20 / 甜 18 / 气泡 40 | ABV 8–13 · 糖 5–10 · 酸 3–6 |
| Short 短饮 | 主料 40 / 酒 40 / 酸 10 / 甜 8 | ABV 14–22 · 糖 4–10 · 酸 2–6 |
| Mocktail 无酒精 | 主料 40 / 酸 20 / 甜 15 / 气泡 80 | ABV 0 · 糖 4–10 · 酸 3–7 |

模板只写「需要什么角色、多少」，不写具体材料——具体材料由用户勾的东西和补位池决定。这样同一套模板能长在草莓、菠萝、黄瓜上。

### 打分

```
40 × 覆盖（风味族覆盖 / 4）
25 × 协同（有 up 型交互 +0.6，族 ≥2 +0.2，主料 ≥2 +0.2）
20 × 平衡（ABV / 糖 / 酸 三项落在目标区间的程度，权重 4:3:3）
10 × 新颖（不同材料数 / 4）
 5 × 简易（做法步数越少越高）
+ mood 偏置（清爽→高球/菲士加，浓郁→短饮加，等）
```

### 「想喝」怎么影响结果

`MOOD_BIAS` 是一张 5×5 的表：清爽 / 浓郁 / 酸甜 / 苦烈 / 温暖，对五个骨架各有加减（-8 ~ +12）。所以换一个调性，排序会整条变，而不是只改标题。

## 3 · 三个真 bug（都是做的时候才发现的）

**① 主角分子按阈值选错了。**
草莓的分子里阈值最低的是 (Z)-3-己烯醛（青绿，0.0005 mg/L），按「最低阈值优先」会拿它当主角，于是「为什么」里写的是青草味——但草莓的主调是熟果甜香。

改法：先按 **level 权重**（dominant 3 / high 2 / mid 1 / low 0.5）排，同权重再比阈值。阈值代表「多容易被闻到」，level 代表「这一项里它是不是主角」，后者才是选主角的依据。

**② 缺什么 跨模板串了。**
`borrowed` 数组曾定义在循环外，五张卡往里累加，结果每张卡都显示同一句「用到了青柠、蜂蜜糖浆、苏打水」——连根本没放苏打水的 Sour 也说有苏打水。

改法：`borrowed` 移到每张卡内部，按「这杯的 lines 里有哪些 id 不在用户勾选里」现算。

**③ 勾了酒却推荐无酒精，没有任何提示。**
用户勾了伏特加，第一名的却是 0.0% 的草莓气泡（因为「清爽」给 mocktail +6）。算得对，但不对味。

改法：如果用户勾了基酒、而这张卡不用酒，**扣 12 分**，并把「缺什么」换成一句直话：*你勾了伏特加，这杯没放酒——想做有酒精的把「无酒精」关掉。*

## 4 · 现在还不能做的

| 缺什么 | 后果 |
|---|---|
| 多主料组合 | 现在只用「第一主料」，勾了草莓 + 菠萝也只会各自出 5 杯，不会出现草莓 + 菠萝 |
| 技法（`data/techniques.json` 没有） | 卡上只能给「摇/直调」，给不出「低温慢煮 65℃」这类 |
| `data/pairs.json`（0 条） | 「协同」分只能靠 rules.ts 那 9 条，不是真正的分子配对 |
| 保存 / 导出 | 「送进配方台」能带走配比，但存不下来 |
| 手机断点 | 1440 下正常，窄屏会挤 |

## 5 · 下一步的优先级（我的建议）

1. **多主料**：允许 2 个主料进同一张卡（现在是最明显的短板）。
2. **补 30 个常用结构式**，让分子页有图可看。
3. **保存 / 导出配方卡**，让它真的能用。
