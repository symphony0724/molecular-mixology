# 07 · 功能分区（四个模式）

> 用户指示（2026-11-10）：「分成几个不同的功能吧，根据现有食材推荐一个，自己试验一个」。
> 本文定义产品的顶层结构。**导航按"要做的事"划分，不按"数据种类"划分。**

---

## 0. 为什么改

v0.1 的导航是「食材库 / 分子库 / 搭配实验室 / 特调工作台 / 技法库 / 配方本」——
这是**按内容类型**分的，用户打开后仍然不知道"我现在该点哪个"。

真实使用只有三种意图，加上一个查阅动作：

| 用户此刻的状态 | 他想要的动作 | 对应模式 |
|---|---|---|
| 手头有东西，不知道做什么 | 给我方案 | **① 推荐台** |
| 有想法，想调到满意 | 让我自己调，边调边看反馈 | **② 试验台** |
| 想搞明白"为什么会这样" | 让我拆到分子层做实验 | **③ 分子台** |
| 单纯想查 | 快速查到 | **④ 资料库** |

前三个是**功能**，第四个是**底座**。顶部导航：`推荐 · 试验 · 分子 · 资料`。

## ① 推荐台「有什么做什么」

**一句话**：告诉我你有什么，我给你 3 杯能立刻做出来的方案，并说清为什么。

### 输入（一屏两步，30 秒完成）

1. **我的材料**：分类勾选（基酒/利口/果汁/糖浆/苦精/香料/乳制品/气泡/其他）
   ＋ 自由输入（"梅斯卡尔、柚子、蜂蜜、一罐气泡水"也能直接识别）
   ＋ 记住上次的「我的酒柜」，下次自动带入
2. **我想要**：口味倾向（清爽 / 浓郁 / 酸甜 / 苦烈 / 温暖辛香）、酒精或无酒精、
   动手时间（<2 min / <10 min / 不限）、杯数

### 输出：3–5 张方案卡

每张卡必须有：

- **名字**（自动生成但可改，如「烟熏柚子气泡」）
- **配料表 + 比例**（单位可切 ml/oz/dash）
- **做法**（摇/搅/直调 + 冰型 + 装饰 + 时间）
- **成品预估**：ABV、糖度、总酸、稀释率、杯型
- **为什么是这杯**（2–3 条，一条感官、一条化学、一条实操）
- **风险提示**（"柚子白瓤压太重会苦"、"这杯成品 ABV 24%，香气会被压住，建议加大冰")
- **缺什么**：若只差 1 样材料，明确标出来（"缺 1 dash 苦精，可用 5 ml 金巴利替代"）

### 交互

`换一批`（保证不与已展示的重复）· `再清爽一点 / 再烈一点`（调整评分权重后重出）·
`就做这杯`（一键送进试验台继续微调）· `收藏`

### 推荐引擎（必须可解释，不能是黑箱）

**第一步 · 配方骨架匹配。** 内置约 20 个"骨架"，每个骨架定义角色与用量区间：

| 骨架 | 角色构成 | 基准区间 |
|---|---|---|
| Sour | 基酒 / 酸 / 甜 / 可选修饰 | 45–60 / 20–30 / 15–25 ml |
| Highball | 基酒 / 长饮稀释 / 可选酸 | 45 / 90–120 ml |
| Old Fashioned | 烈酒 / 糖 / 苦精 | 60 / 5–7.5 ml / 2–3 dash |
| Martini | 烈酒 / 加强酒 | 60 / 10–15 ml |
| Fizz / Collins | 基酒 / 酸 / 甜 / 气泡 | 45 / 25 / 20 / 60 |
| Tiki | 基酒 ×2 / 酸 / 糖浆 / 香料 | 30+30 / 25 / 15 |
| Flip / 奶洗 | 基酒 / 乳 / 糖 / 蛋 | 45 / 20–30 / 10 / 1 |
| 酸调（Acid-adjusted） | 烈酒 / 酸粉溶液 / 糖浆 / 水 | 60 / 10 / 10 / 20 |
| Mocktail | 无醇基底 / 酸 / 甜 / 气泡 / 苦 | 90 / 20 / 15 / 60 |

**第二步 · 用现有材料填充角色。** 每个食材带 `roles[]` 标签
（`base-spirit` / `acid-juice` / `sweetener` / `bitter` / `aromatic` / `dairy` / `sparkling` …），
用标签匹配，缺口才算"缺材料"。

**第三步 · 打分排序。**

| 维度 | 权重 | 依据 |
|---|---|---|
| 角色覆盖度 | 40% | 骨架是否填满；缺 1 项扣分但不淘汰 |
| 风味协同 | 25% | 共享分子族 + 协同规则加分；冲突规则重扣 |
| 平衡预测 | 20% | 酸甜比是否落在骨架的经典区间；成品 ABV 是否在 12–18%（或骨架对应区间） |
| 新颖度 | 10% | 与已展示方案、用户历史配方的差异度 |
| 简易度 | 5% | 步骤数、是否需特殊设备 |

**第四步 · 生成解释。** 每条方案必须能回答"为什么是这个组合"——直接复用
`docs/04-交互规则原型.md` 的规则库与分子共享关系。**没有解释的方案不予展示。**

## ② 试验台「自己配一个」

**一句话**：自己往里加东西，实时看到它变成什么样，包括会翻车的地方。

### 布局

```
┌──────────────────────┬──────────────────────┐
│ 杯子（体积分层可视化） │ 实时读数             │
│   ▓▓▓ 基酒 45         │ ABV 16.2%  糖 12 g/100 │
│   ▓▓ 酸 25            │ 总酸 6.8 g/L  pH≈4.2  │
│   ▓ 糖浆 15           │ 体积 95 → 稀释后 118   │
│   ▓ 气泡 60           │ 风味雷达 / 风味族条    │
├──────────────────────┴──────────────────────┤
│ + 添加食材（搜索）                            │
│ 交互提示（按影响排序，最多 5 条可展开）        │
│ ⚠ 柚子皮 + 奶油：会浑浊（若你要奶洗，这正是想要的）│
│ ✓ 蜂蜜 + 梅斯卡尔：烟熏酚类与花香叠加，层次好   │
│ 技法推荐：适合奶洗 / 不适合乳化                │
│ [生成步骤] [起名] [保存] [送配方卡]            │
└─────────────────────────────────────────────┘
```

### 关键设计

- **滑块调量，实时重算**：拖动柠檬汁从 15→30 ml，酸度、pH、风味雷达、提示一起变。
- **杯子可视化**：按体积画液层，颜色按食材色混合（近似 LAB 混色，不做精确）。
- **不评判**：提示语用"这会很酸，你确定吗？"而不是"错误"。因为酸到 8 g/L 在某些风格里是对的。
- **提示排序**：按影响强度，最多 5 条；"全部展开"给完整列表。
- **步骤生成**：根据选定技法输出可执行流程（含时间、温度、过滤），可直接进配方卡。
- **起名**：按主导风味族 + 技法 + 最强修饰，如「烟熏 · 奶洗 · 柚子」。

## ③ 分子台「造一个」

完整设计见 **[06-分子操作台.md](06-分子操作台.md)**。三模式：工坊 / 反应台 / 映射。

它与试验台的分工：
- **试验台**在「食材层」操作，输出是一杯酒。
- **分子台**在「分子层」操作，输出是**一个新风味**，再通过映射台反查"现实中怎么得到它"。

链路：`分子台 → 得到目标风味 → 映射台反查食材与用量 → 送进试验台调比例`。

## ④ 资料库（底座，不是功能）

统一全局搜索（`⌘K` / 手机搜索条），可搜：食材、分子、反应、技法、名词。
分四个标签页：**食材 · 分子 · 反应 · 技法**。
任何模式里出现的名字（食材/分子/技法）都可点击跳到对应条目。

## 共享引擎（架构关键）

四个模式共用同一个 `Engine`，**不能各写一套**：

```
Engine
├─ DataStore     加载 JSON、索引（按 id / 角色 / 风味族 / 分子）
├─ RoleMatcher   食材 → 角色标签匹配（推荐台填骨架、试验台校验）
├─ InteractionSolver  两两/多材交互求解（返回按影响排序的结论 + 机理 + 建议）
├─ ReactionSolver     分子级反应求解（条件区间判定 + 产物 + 速率）
├─ Calc           ABV / 糖度 / 总酸 / pH / 稀释 / 体积 / 阈值倍数
├─ Explainer      把求解结果转成人话（模板化，可追溯来源）
└─ Store          IndexedDB：我的酒柜 / 配方 / 实验记录 / 偏好
```

这样做的直接好处：**推荐台生成的一杯，进试验台可以继续改；试验台导出的一杯，
可以拆进分子台看它的分子构成。** 三个模式是同一件事的三个深度，不是三个独立产品。

## 模式与旧模块（M1–M10）的映射

| 旧模块 | 去向 |
|---|---|
| M1 食材库 / M2 分子库 / M6 技法库 | → ④ 资料库（底座） |
| M3 交互引擎 | → 共享 `InteractionSolver`，在 ② 试验台与 ① 推荐台的"为什么"里呈现 |
| M4 风味可视化 | → ② 试验台读数面板 + ④ 资料库详情页 |
| M5 特调工作台 | → ② 试验台（改名，因为"工作台"听起来像工具而非体验） |
| M7 配方本 | → 全局（顶部头像菜单），不属于任何模式 |
| M8 学习模式 | → ④ 资料库的"原理"标签 + ① 的"为什么"（融入，不单列） |
| M9 分子操作台 | → ③ 分子台 |
| M10 无酒精模式 | → 全局开关（影响 ①②③） |

## 首版顺序（建议）

1. ② 试验台 —— 它是所有能力的"显示屏"，数据对不对立刻看得见，也最容易自己用起来。
2. ④ 资料库 —— 数据可视化，靠它验证 60+120 条数据质量。
3. ① 推荐台 —— 依赖骨架库与评分，数据稳定后再做，避免反复调权重。
4. ③ 分子台 —— 独立性强、可最后做；但先把 `Reaction` 数据表备好。
