# 03 · 数据模型草案

目标：**纯静态 JSON，前端即可查询**；结构留出扩展余地。以下为 TypeScript 风格的类型草案。

## 1. 食材 Ingredient

```ts
interface Ingredient {
  id: string;              // "gin-london-dry"
  name: string;            // "伦敦干金酒"
  nameEn: string;          // "London Dry Gin"
  aliases: string[];       // ["金酒", "琴酒", "杜松子酒"]
  category: Category;      // 见下
  subcategory?: string;
  // 量化属性（区间优于单值，文献差异大）
  abv?: number;            // 体积百分比，0–95
  sugar?: number;          // g/100 mL
  pH?: number;
  totalAcid?: number;      // g/L 以柠檬酸计
  bitterness?: number;     // 0–10 自定义苦感指数
  body?: number;           // 0–5 醇厚/口感
  color?: string;          // hex 近似色
  // 感官
  flavorFamilies: Record<FlavorFamily, number>; // 0–5
  keyCompounds: CompoundRef[];  // 关键分子（含相对含量等级）
  // 用途
  typicalUse?: string;     // "基酒 45–60 ml"
  notes?: string;          // 工艺/产地/挑选要点
  sources?: Source[];
}

interface CompoundRef {
  id: string;              // 指向 Compound
  level: "trace" | "low" | "medium" | "high" | "dominant";
  role?: "character" | "supporting" | "off-note"; // 特征/辅助/异味
}
```

`Category` 枚举：`spirit | liqueur | wine | juice | syrup | bitter | dairy | egg | herb_spice |
tea_coffee | sparkling | pantry | other`

`FlavorFamily` 枚举：`fruity | citrus | floral | herbal | spicy | woody | roasted | creamy |
smoky | earthy | sulfury | fermented | resinous | nutty | green`

## 2. 分子 Compound

```ts
interface Compound {
  id: string;              // "isoamyl-acetate"
  name: string; nameEn: string;
  cas?: string;
  formula?: string;        // "C7H14O2"
  flavorFamily: FlavorFamily;
  odorDescription: string; // "香蕉、梨、糖果"
  thresholdWater?: [number, number] | number; // mg/L，区间表示文献差异
  thresholdEthanol?: number;                   // 乙醇基质中阈值（通常更高）
  bp?: number;             // 沸点 °C
  logP?: number;           // 亲脂性
  solubility?: "water" | "ethanol" | "fat" | "both";
  stability?: string;      // "碱性水解；光照氧化"
  foundIn?: string[];      // 食材 id 列表（可由 Ingredient 反推，冗余便于查询）
  sources?: Source[];
}

interface Source {
  label: string;           // "《Food Chemistry》第5版"
  url?: string;
  confidence: "high" | "medium" | "low";
}
```

## 3. 交互 Interaction

```ts
type InteractionKind =
  | "synergy"     // 协同增效
  | "masking"     // 掩蔽
  | "suppression" // 抑制
  | "additive"    // 简单叠加
  | "chemical"    // 化学反应
  | "physical"    // 物理变化
  | "neutral";

type Verdict = "recommend" | "caution" | "avoid";

interface Interaction {
  id: string;
  a: string;               // ingredient id 或 compound id 或 "*"(通配)
  b: string;
  kind: InteractionKind;
  verdict: Verdict;
  score: number;           // -5 到 +5，用于矩阵热力图与排序
  title: string;           // "柑橘皮 + 奶油 → 奶洗澄清"
  mechanism: string;       // 化学/感官机理，必须写
  advice: string;          // 操作建议
  condition?: string;      // "pH < 4.6" / "酒精度 > 20%" / "需加热 > 120 °C"
  evidence: "literature" | "mechanism" | "consensus" | "unverified";
  tags?: string[];         // ["milk-washing", "clarification"]
  sources?: Source[];
}
```

**规则引擎设计要点（重要）**

1. 大部分规则写成**通配规则**，用角色标签匹配，而不是穷举食材对：
   `{ a: "role:citrus-juice", b: "role:dairy", ... }`，
   这样 60 个食材 × 60 = 3600 对不必手写，靠"角色 + 分子族"推导。
2. 具体规则（少数高价值对）覆盖通配规则（优先级：具体 > 通配）。
3. 每条输出都要带 `mechanism`，UI 永远能回答"为什么"。

## 4. 配方 Recipe

```ts
interface RecipeItem {
  ingredientId: string;
  amount: number;
  unit: "ml" | "oz" | "dash" | "barspoon" | "tsp" | "g" | "piece";
}

interface Recipe {
  id: string;
  name: string;
  author?: string;
  items: RecipeItem[];
  method: "shake" | "stir" | "build" | "blend" | "throw" | "milk-wash" | "carbonate";
  ice?: string;
  dilutionOverride?: number; // 手动指定稀释率 0–0.35
  glass?: string;
  garnish?: string;
  process?: Step[];          // 步骤，含浸泡/静置/过滤时间
  computed?: {               // 由工作台计算，不入库
    abv: number; sugar: number; totalAcid: number; ph?: number;
    volume: number; dilution: number;
  };
  rating?: number; notes?: string;
  createdAt: string; updatedAt: string;
}
```

## 5. 计算所需辅助数据

- **ABV 与密度换算表**：乙醇-水溶液的体积分数 ↔ 密度（20 °C），用于按质量/体积准确算 ABV。
- **糖度表**：不同糖浆的 g/100 mL（简单糖浆 1:1 ≈ 48 g/100 mL；2:1 ≈ 65 g/100 mL）。
- **酸当量表**：柠檬酸 / 苹果酸 / 酒石酸 / 乳酸 / 磷酸的相对酸强度与当量换算。
- **单位换算**：1 dash ≈ 0.6 ml（苦精瓶差异大，允许自定义）、1 barspoon ≈ 5 ml、1 oz = 29.57 ml。
- **风味平衡参考区间**（来自经典配方统计）：
  - Sour 家族 sour:sweet ≈ 1:1 ~ 1:1.5，成品 ABV 12–18%
  - Highball 成品 ABV 5–8%，稀释 40–60%
  - Old Fashioned 类 甜度低、苦精 1–3 dash

## 6. 反应 Reaction（分子操作台用）

完整定义见 **[06-分子操作台.md](06-分子操作台.md) §7**。要点：

- `reactants[].match` 支持 `compound id` / `role:*` / `class:*` 三种匹配方式（与交互规则同一套通配思想）；
- `conditions` 用区间 `[min, max]` 表达，UI 拨盘实时判定是否成立，不成立时显示"还差什么"；
- `rate` 必须填（instant / minutes / hours / days / weeks / negligible），台面据此用时间尺度点亮；
- `mechanism` 与 `evidence` 必填，缺失即视为不合格数据。

## 7. 文件组织建议

```
data/
  ingredients/spirits.json, liqueurs.json, juices.json, ...
  compounds.json
  interactions/sensory.json, chemical.json, physical.json
  techniques.json
  reference/units.json, acids.json, density.json
```

构建时合并为单文件，前端一次性加载（gzip 后预计 < 300 KB）。
